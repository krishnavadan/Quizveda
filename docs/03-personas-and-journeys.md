# Personas and User Journeys

## Personas
- **Curious guest:** wants to start instantly and explore varied topics without registration.
- **Learner:** wants explanations, practice and progress feedback.
- **Professional:** wants relevant applied questions but retains freedom to browse every subject.
- **Educator/content author:** creates structured question packs and needs validation/review feedback.
- **Reviewer/publisher:** ensures accuracy, rights, quality and safe release.
- **Support/admin:** resolves issues with least-privilege, audited access.

## Journey A — Guest play
Landing → browse catalog → choose mode/topic/difficulty → start → answer sequence → result/explanations → optional sign-up prompt. Sign-up must not block result access.

## Journey B — Profile-aware play
Create account → optional profile → select interests/goal → recommendation with reason → user edits selection → session. Explicit selections always override recommendation.

## Journey C — Learning practice
Choose topic → choose Practice → answer → view explanation/source → continue → progress summary → suggested next practice.

## Journey D — Content publishing
Author creates pack → uploads JSON → dry-run validation → fixes errors → submits review → reviewer approves → publisher previews staging → publishes → monitors → rollback if necessary.

## UX principles
Low-friction entry, transparent recommendations, no shaming labels, clear timer state, accessible controls, localized content, visible ability to change difficulty/topic and disable personalization.
